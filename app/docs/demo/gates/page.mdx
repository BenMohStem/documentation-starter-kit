## The release battery

Every release runs the same battery, in the same order, and every
stage must pass or there is no release:

1. **Source gate** — the build compiles clean under strict flags:
   every warning an error, sanitizers armed;
2. **Oracle gate** — every subsystem's independent oracle runs green,
   and the negative controls fail *as designed* — a control that
   cannot fail proves nothing;
3. **Sanitizer gate** — address, undefined behavior, and leak checks
   across the full workload set;
4. **Determinism gate** — recorded inputs replay to identical state,
   byte for byte;
5. **Demo gate** — the playable demonstration runs the complete arc,
   start to finish, on the release binary.

## The retraction stories

The strictness is not temperament. It is scar tissue:

> Twice, a promoted result turned out to be a measurement artifact.
> A layout "win" of 1.44× died to fresh-process repetition — the
> noise between runs was larger than the effect. A churn benchmark
> turned out to have never run its declared workload at all: a
> selector formula capped executed mutations at a fraction of what
> was stated, and the corrected benchmark *reversed* the conclusion.
> Both times: caught, retracted the same session, and the rules made
> stronger. Both stories are kept.
