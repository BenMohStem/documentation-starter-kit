# Integrity Incidents

Error is knowledge. These are the project's recorded failures — kept visible
on purpose.

## The 3.190 defect chain — five gates, five catches

**What happened**: the graph-degree instrument (3.190) entered testing
with four defects, then shipped with a fifth that only post-publication
re-analysis caught:

1. *Deletion without tombstones* — removing an edge by clearing its slot
   broke other keys' probe chains, creating phantom duplicates and a
   wrapped 16-bit degree counter (grid degree read 65534 where truth
   is ≤ 4). Caught by the probe-audit confusion matrix, before any
   policy ran.
2. *Per-rep allocation tax* — re-allocating the 144 MB table every
   repetition charged ~548M first-touch page-fault cycles to the
   selector. Caught by the never-lose battery (the selector "lost" on
   a family where it declines to act), then attributed by a
   cost-breakdown diagnostic.
3. *A degenerate hash* — `key ^ (key>>32)` maps half of all grid edges
   `(a, a+1)` to a single slot; every mutation walked a ~16K-long
   probe chain (15,000 cycles/record). Caught by the same diagnostic
   showing 50M maintain-cycles per frame.
4. *A record-stream misread* — mutation records are emitted in pairs
   (inherited semantics), and the table consumed both; the second
   record's uninitialized old-endpoints randomly deleted real edges
   while doubled multiplicities made stale ones linger. The audit's
   own "fires through 20% churn" was wrong; the clean envelope is
   10%. Caught by a semantic audit of the stream *before the report
   was written* — every published number re-derived after the fix.
5. *A 64× overallocation* — the capacity macro's thresholds were
   written for log2(nb) but received raw nb, so every scale allocated
   a 167 MB table (the registered size at 32K is 2.6 MB). It survived
   every gate: content is capacity-independent, and every policy was
   priced against the same inflated table, so comparisons looked
   fair. Caught *after publication* by refusing to believe a measured
   110M-cycle rebuild that an insert-cost model said should be ~10M.
   The published never-lose prices collapsed from +10–15 to +2–4 and
   the published mix verdict flipped — corrected in public, error
   left visible.

**How each was caught**: four by gates built from previous incidents
(3.157, 3.185-1, 3.189-1 created the audit, the anchor cross-check, the
cost diagnostic); the fifth by the only detector that could see it —
an independent cost model. The new standing law: **every published
cost number must survive a back-of-envelope check (bytes moved × access
cost + instructions); a measurement that flatters expectations deserves
the same suspicion as one that contradicts them.**

**Class**: implementation-defect family (no decision constant was
tuned at any point — thresholds stayed frozen per the registration).
The five fixes changed cost or correctness of the instrument, never
the rules it decides by.

## Incident 3.189-1 — The contaminated battery

**What happened**: a fresh-process timing battery was launched while 128K and
256K verification runs held the same pinned measurement core. The
contaminated battery showed never-reorder at 157 cycles/contact — its true
value is ~51 — with 2–3× inflated noise floors.

**How it was caught**: cross-checking the battery's numbers against a
known-clean anchor run from the same session. The numbers disagreed with
the anchor by 3×; the concurrent jobs were the only difference.

**Correction**: both background jobs were killed, the battery was re-run
clean, and only the clean run was recorded. The general law is now
standing: **never run timing batteries concurrently with other pinned
work** — concurrent load on the pinned core invalidates timing, and the
check that catches it is a clean-anchor comparison.

**Class**: the 3.185-1 measurement-validity family — a measurement whose
conditions silently changed. Third recorded instance; all permanent.

## The probe-audit refutation (3.189, ancestor discipline)

The first chain-detection probe passed review and then failed its own
instrument audit: measured against all topology families *before any
policy claim*, it fired on grids and hubs (both walk through the contact
array, as chains do). Two pre-registered predictions were wrong. The
fix — a third clause separating index-local traces from
scatter-jumping ones — was itself pre-registered before any policy
timing. Rule promoted to doctrine: **a measurement instrument gets a
confusion matrix over all workload families before it can gate a claim.**

## Incident 3.185-1 — The promotion that was noise

**What happened**: a span-triggered rebuild policy measured 1.44x better
than never-reordering at 32K bodies / 10% churn. It passed the oracle, the
negative control, and the sanitizers. It was promoted.

**How it was caught**: fresh-process repetition the same session showed
process-to-process noise (spread 59–302 cycles/contact) larger than the
claimed effect. The promotion was retracted in the same session it was made.

**Root causes**: single-process median-of-3 on a noisy host; no
interleaving of policies, so each policy inherited a different thermal /
scheduler epoch.

**Correction**: interleaved per-frame policy execution, min-of-K statistics,
explicit noise floors, a 2x-noise promotion bar (all promoted to standing
doctrine in 3.186).

**Class**: the 3.157 benchmark-hallucination family — a claim exceeding the
measurement's power. Second recorded instance in project history. Both are
permanent lessons.

## The 3.157 hallucination (ancestor)

The original benchmark-integrity failure: a benchmark report whose numbers
could not have come from the code as built. The response defined the
project's audit culture: stated operator must equal executed operator,
source-audited, oracle-verified.

## The 3.128 operator mismatch

A benchmark's text claimed one operation; the compiled code executed
another (an operator-precedence defect). Passed tests, failed the audit.
Result: the source-audit gate became standing law.

## The energy-cancellation defect

An early solver micro-benchmark where a cancellation in the energy
computation made the measurement nearly meaningless — caught by the
independent high-precision reference. Result: every energy metric now runs
against an independent recomputation.

## The index-local workload (3.186)

An entire family of layout benchmarks ran on a contact builder whose
natural order was already optimal — the baseline could not lose. Result:
the adversarial topology families became the standing workload set.

---

Each incident made the instrument stronger. The current gate battery
(oracle, negative control, sanitizers, noise floors, workload audit) exists
because each of these failures happened once.
